# Vibe Coding 之后怎么继续成长

觉得难是正常的。NearSend 横跨很多层：

```text
UI
状态管理
局域网发现
HTTP 服务
文件传输
Windows 防火墙
Android 网络权限
打包发布
```

这已经不是初学者练手 app，而是一个真实工具型应用。靠 vibe coding 把它跑通，本身已经完成了很重要的一步：把需求和结果拉到现实里。

## 不需要立刻全部手写

更现实的路线是继续使用 AI，但开始有意识地接管小块代码。

可以按这个顺序来：

## 1. 先看懂 UI

从按钮、文本、列表开始。

练习：

- 改一个标题。
- 加一个按钮。
- 改一个弹窗。
- 改一个提示文案。

目标不是马上写完整应用，而是知道“这个界面在哪”。

## 2. 看懂一个功能闭环

比如“一键修复”：

- 按钮在哪里。
- 点击后调用哪个函数。
- 函数跑了什么脚本。
- 成功或失败怎么显示。

先理解一条链，比同时学十门课更有效。

## 3. 手改很小的需求

适合练手的小需求：

- 改按钮禁用条件。
- 多显示一行诊断信息。
- 给消息气泡加复制按钮。
- 改一个状态提示。
- 给某个错误补一条日志。

这种改动小，但能训练你读代码、定位代码、验证代码。

## 4. 最后再理解网络

不要一开始就啃 TCP、UDP、multicast。

先理解这句话：

```text
电脑开了一个 HTTP 服务，平板通过电脑 IP + 端口访问它。
```

这句话足够解释很多问题：

- 为什么 `127.0.0.1` 只能电脑自己访问。
- 为什么要显示 `10.x.x.x:54317`。
- 为什么防火墙会影响平板访问电脑。
- 为什么电脑能发给平板，不代表平板也能发给电脑。

## 推荐心法

不要把目标设成“从今天开始全部手写”。

更好的节奏是：

```text
AI 写 80%，你读懂 20%
AI 写 70%，你改 30%
AI 写 50%，你设计 50%
```

每次只拆一个问题。比如今天只看“发送文字是怎么从按钮到网络请求的”。看懂这一条链，比泛泛学习一堆概念更有效。

Vibe coding 不丢人。它可以是脚手架。真正的成长是逐步把关键模块接管回来。
